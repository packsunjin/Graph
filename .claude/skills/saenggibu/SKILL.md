# 생기부 자기평가서 작성 + 검증관 3명 교차검증

학생과 대화하며 학교 자기평가서 양식을 채우고, 검증관 A(규정)·B(입학사정관)·C(서술) **3명 모두 통과**한 경우에만 최종본으로 내놓는다.

## 0. 시작 전에 읽을 것

1. `saenggibu/guides/작성자가이드.md` — 작성 원칙(반드시 전부 읽기)
2. `saenggibu/README.md`의 핵심 규정 요약표
3. 학교 양식이 없으면 `saenggibu/templates/` 의 양식

검증관 기준서(`guides/검증관*.md`)는 검증관 서브에이전트가 직접 읽는다. 메인 Claude는 판정을 미리 흉내 내지 않는다.

## 절대 원칙

- **결과물은 학생 본인의 1인칭 자기평가서**(교사 참고용)다. 생기부에 그대로 넣을 교사 문체 문장을 대신 써 주지 않는다. 기재요령은 서술형 항목 내용을 학생이 작성해 내게 하는 것과 AI 생성문을 그대로 입력하는 것을 금지한다. 이 점을 처음에 한 번 짧게 안내한다.
- 학생이 말하지 않은 사실(책, 수치, 실험 횟수, 결과, 역할)은 **절대 지어내지 않는다**. 모르면 묻는다.
- **개인정보는 저장소에 커밋하지 않는다.** 학생 이름·학번·학교명·수강신청서·답변·초안·검증 결과는 스크래치패드 디렉터리(있으면) 또는 `saenggibu/work/`(gitignore 됨)에만 저장한다. 이 작업 중에는 `git add`/`git commit`을 하지 않는다.
- 학교명·지역명·학번·이름은 초안 본문에도 쓰지 않는다.

## 1단계 — 학기·학교 양식 확인

AskUserQuestion으로 한 번에 묻는다(4문항 이하, 각 문항 보기 2개 + Other 직접 입력).

- 몇 학년 몇 학기인가
- 작성할 양식: 창체 / 교과 세특 / 둘 다
- 학교 양식 파일이 있는가(있으면 경로를 받아 읽고 섹션 구조·과목명·문장 수 제한·선택지를 그대로 따른다. 없으면 `templates/` 기본 양식 사용)
- 교과라면 과목 목록과 각 과목이 **공통과목인지 선택과목인지**(공통과목은 1·2 합산 500자, 선택과목은 과목별 500자). 공통과목·창체라면 이전 학기에 쓴 분량을 아는지

학교 양식을 읽고 나면 섹션 목록을 학생에게 한 줄로 보여 주고 확인받는다.

## 2단계 — 섹션별 질문 (AskUserQuestion)

- 한 번에 **한 섹션**만 다룬다(예: 자율·자치 → 동아리 → 진로 → 과목1 → …).
- 한 섹션당 AskUserQuestion **질문 4개 이하**. 각 질문은 **보기 2개**를 주고, 학생은 보기를 고르거나 **Other(직접 입력)**로 자기 경험을 쓴다. 보기는 "이런 방향인가요?" 수준의 일반적인 예로만 만들고, 학생 대신 사실을 정해 주지 않는다.
- 우선 물을 것(양식 칸 순서): 수업 맥락·단원 / 처음 생긴 질문 / 읽은 책(제목·저자, 질문과의 연결) / 탐구 주제·방법(4개 중 택1)·수업 중 했는지 / 막혔던 지점과 고친 방법 / 결과·한계 / 강조 역량(15개 중 1~2) / 실제로 실천할 계획.
- 4문항으로 부족하면 같은 섹션에서 한 번 더 묻는다(역시 4문항 이하). 답이 금지 사항(대회·수상, 외부 기관·대학명, 논문 투고, 어학시험, 부모 직업, 학원 등)이면 그 사실은 쓰지 않는다고 설명하고 대체 재료를 묻는다.
- 답변은 작업 파일(스크래치/`saenggibu/work/`)에 섹션별로 저장한다.

## 3단계 — 1인칭 자기평가서 초안

- `작성자가이드.md`의 원칙과 매핑표를 따른다. 양식 칸 순서·문장 수 제한을 지킨다. 칸을 비우지 않는다(정보가 없으면 질문으로 돌아간다).
- 섹션별로 Bash로 글자 수와 NEIS Byte를 계산해 둔다(UTF-8 바이트 수가 NEIS 기준과 같다: 한글 3, 영문·숫자·공백·엔터 1).
  ```bash
  python3 -c "import sys;t=sys.stdin.read().rstrip('\n');print(len(t),'자 /',len(t.encode('utf-8')),'Byte')" < 섹션파일.txt
  ```
- 학생이 원하면 섹션마다 "교사 참고용 예상 세특 방향" 메모(명사형 종결, 이름 없음, 분량 한도 안)를 짧게 덧붙일 수 있다. 메모에는 "교사 참고용"이라고 표시한다.
- 초안은 작업 파일(예: `초안_<양식>_v1.md`)로 저장한다.

## 4단계 — 검증관 3명 독립 판정 (병렬)

- **한 메시지에서 Agent(Task) 도구를 3번 동시에 호출**한다. 서로의 결과를 넘겨주지 않는다(협의 금지).
  - `saenggibu-verifier-rules` (검증관 A, 규정)
  - `saenggibu-verifier-admissions` (검증관 B, 입학사정관)
  - `saenggibu-verifier-writing` (검증관 C, 서술)
- 각 프롬프트에 똑같이 넣을 것: 초안 파일 경로(또는 본문), 학년·학기, 양식 종류, 섹션 목록과 섹션 유형(창체 / 공통과목 / 선택과목), 섹션별 글자 수·Byte, 이전 학기 사용 분량(알면), 재검증 회차.
- 학생 이름·학번·학교명은 프롬프트에 넣지 않는다.
- 결과는 작업 파일(`검증A_<양식>_v<n>.md` 등)로 저장한다.

## 5단계 — 종합

- **세 검증관이 모두 모든 섹션을 '통과'로 판정**했을 때만 최종본으로 확정한다.
- 하나라도 '반려' 또는 '조건부 통과'면 최종본이 아니다. 6단계로 간다.
- 검증관끼리 의견이 다르면 더 엄격한 쪽을 따른다(규정 위반 가능성은 A를 우선).

## 6단계 — 되묻기 → 재작성 → 재검증 (최대 3회)

1. 검증 결과를 섹션별로 학생이 이해하기 쉽게 요약한다(규칙번호는 괄호로만).
2. 검증관이 낸 학생 질문(각 최대 3개)을 합쳐 중복을 없애고, AskUserQuestion으로 묻는다(한 번에 4문항 이하, 보기 2개 + Other).
3. 답을 반영해 해당 섹션만 고친다(v2, v3 …). 학생 답이 없는 부분은 지어내지 않고 빼거나 질문으로 남긴다.
4. 4단계를 다시 실행한다. 재검증에서는 3명 모두 다시 호출한다(통과했던 검증관 포함).
5. **재검증 루프는 최대 3회.** 3회 후에도 통과하지 못하면 멈추고, 남은 쟁점을 섹션·검증관·규칙번호별로 표로 정리해 학생에게 보고하고 선택(직접 수정 / 해당 내용 삭제 / 선생님께 확인)을 맡긴다.

## 7단계 — 최종본 전달

- 최종 자기평가서를 양식 순서대로 보여 주고 작업 파일(`최종_<양식>.md`)로 저장한다.
- 함께 안내할 것:
  - 학교 양식에 **직접 옮겨 쓰면서 자기 말투로 다듬을 것**(AI 생성문 그대로 제출 금지)
  - 학교의 AI 사용 규칙·제출 마감·분량을 선생님 안내로 확인할 것
  - 추후 계획은 실제로 실천할 것
  - 규정은 2026학년도 기재요령 기준이며 매년 바뀔 수 있음
- 작업 파일은 커밋하지 않는다고 다시 알린다.
